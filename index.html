03 · graduation capstone

Memora: AI that reads brain MRI scans.

A deep learning system that classifies Alzheimer's severity from MRI, wrapped in a full clinical platform for patients, doctors and families. I led the documentation for a five-person team.

99.91%test accuracy
15,000MRI images
14entity schema
145pages of docs
My role

Wrote the full technical documentation: architecture, database design, requirements and evaluation. Worked with the team on preparing the dataset and training the model.

Requirements

Functional requirements split by the four roles (patient, doctor, family, admin) so every feature traces to who needs it. Non-functional targets are measurable: API responses under 2 s, MRI classification under 5 s, bcrypt hashing and JWT-protected endpoints.

The model

Optuna searched six architectures and settled on EfficientNetB6 with AdamW. Images fed at 528×528, the network's native size, so fine detail wasn't lost. Two-stage training: the new head first, then fine-tuning the top layers.

Data & security

SQLite through a SQLAlchemy ORM to keep raw SQL away from patient data, write-ahead logging for concurrency, and a clear migration path to PostgreSQL.

memora_oracle_schema.sqlported to Oracle 12c+
CREATE TABLE diagnoses (
  id             NUMBER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  patient_id     NUMBER NOT NULL,
  doctor_id      NUMBER NOT NULL,
  classification VARCHAR2(30) NOT NULL,
  status         VARCHAR2(10) DEFAULT 'pending' NOT NULL,
  CONSTRAINT ck_diag_status CHECK (status IN ('pending','completed'))
);

-- Patients only see a diagnosis after the doctor approves it
CREATE OR REPLACE VIEW v_patient_visible_diagnoses AS
SELECT id, patient_id, classification FROM diagnoses WHERE status = 'completed';

-- MMSE score change since each patient's previous test
SELECT patient_id, total_score,
       total_score - LAG(total_score) OVER (PARTITION BY patient_id ORDER BY created_at) AS change
FROM mmse_results;
04 · found & fixed

I audit my own code like an attacker.

Every product went through an OWASP Top 10 review before release. A few of the issues I found, and how they were closed.

HIGH
Installer takeover after redeploy
RiskIf the install lock file was lost, anyone could re-run the installer, create a Super Admin and point the app at their own database.
FixThe installer now also refuses when a Super Admin already exists in the database, and recreates the lock.
ClinicFlow
HIGH
SSRF through outgoing webhooks
RiskA webhook URL could be aimed at internal or special IP ranges, turning the server into a proxy into private networks.
FixResolved addresses are checked against private, loopback and reserved ranges before any request leaves.
ReplyFlow
MED
Host-header password-reset poisoning
RiskA forged Host header could make reset e-mails link to an attacker's domain and leak the reset token.
FixLinks are built from the configured app URL only, and reset responses no longer reveal which accounts exist.
ReplyFlow
MED
Open redirect in language switch
RiskThe switcher redirected to whatever the Referer header said, a ready-made link for phishing.
FixRedirects are limited to pages on the same site.

05 · network design

A software company, three floors deep.

Designed and built in Cisco Packet Tracer as a group project: management on the third floor, staff on the second and the server room on the first, linked by fiber and RIP routing.

How it works

A DHCP server hands out addresses, a DNS server resolves names, and an IoT server collects data from the smart and security devices. Each router interface is the default gateway for its subnet, and RIP routes between 192.168.4.0 and 192.168.5.0.

DHCPDNSIoT serverRIPfiber between floorswireless APsping · packet tracing
How I would harden it today
  • Separate VLANs for staff, servers and IoT
  • ACLs so cameras and sensors can't reach staff PCs
  • OSPF with authentication instead of RIP
  • WPA2-Enterprise and central logging into a SIEM
